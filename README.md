# Анализ лояльности пользователей Яндекс Афиши

Приложение воспроизводит исследование повторных покупок за июнь-октябрь
2024 года. Оно загружает SQL-выгрузку заказов, приводит выручку к рублям,
очищает данные, строит профили пользователей и сравнивает возврат по
сегментам. Логика собрана в классе `DataProcessor`, запуск выполняет `main.py`.

## Структура

| Файл или папка | Назначение |
| --- | --- |
| `main.py` | Последовательный запуск обработки и вывод итогового отчета |
| `src/processing.py` | Класс `DataProcessor` с обработкой и анализом |
| `src/query.sql` | SQL для выгрузки заказов из учебной БД |
| `.env.example` | Шаблон параметров подключения без учетных данных |
| `requirements.txt` | Зафиксированные версии библиотек |
| `tests/test_processing.py` | Проверки очистки, профилей и окна возврата |
| `data/` | Локальные исходные CSV, исключены из Git |
| `results/` | Локальные результаты анализа, исключены из Git |

## Установка и запуск

Проверено с Python 3.12.7. Зависимости устанавливаются один раз при
подготовке окружения. Приложение не устанавливает библиотеки при запуске.

```bash
git clone https://github.com/lmncrtD/project-seven-sprint.git
cd project-seven-sprint
python3 -m venv venv
source venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
mkdir -p data
```

В Windows после клонирования используйте PowerShell:

```powershell
py -3.12 -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
New-Item -ItemType Directory -Force data
```

Поместите в `data/` два файла:

- `orders.csv`: результат запроса `src/query.sql` из учебной базы Яндекс Афиши.
- `final_tickets_tenge_df.csv`: [дневной курс тенге к рублю](https://code.s3.yandex.net/datasets/final_tickets_tenge_df.csv).

Для подключения к БД заполните в локальном `.env` переменные `DB_HOST`,
`DB_PORT`, `DB_NAME`, `DB_USER` и `DB_PASSWORD`. `DB_SSLMODE` по умолчанию
равен `require`. При отсутствии `data/orders.csv` приложение выполнит
`src/query.sql` через подключение только для чтения и сохранит CSV.
При наличии выгрузки подключение к БД не требуется. Файл курса нужен
в обоих случаях. Данные и действующий `.env` не хранятся в репозитории.

Запуск из активированного окружения:

```bash
python3 main.py
```

В Windows:

```powershell
python main.py
```

Отчет выводится в терминал. В `results/` сохраняются Markdown-отчет,
контрольные показатели в JSON, профили пользователей, таблицы сегментов,
матрицы PhiK и 11 графиков PNG. Графики сохраняются без открытия окон.

## Обработка данных

SQL оставляет заказы с устройств `mobile` и `desktop` и исключает фильмы.
Пользовательские идентификаторы читаются как строки, чтобы сохранить
ведущие нули. Даты и время обрабатываются в московском времени исходной
выгрузки. Интервалы между заказами считаются в календарных днях.

Неявные дубликаты определяются по сочетанию `user_id`, `order_ts`,
`device_type_canonical`, `service_name`, `event_id`, `revenue`. Сохраняется
строка с минимальным `order_id`. По этим данным нельзя окончательно
установить причину появления таких совпадений.

Выручка в тенге переводится по дневному курсу `curs / nominal`. Даты курса
должны быть уникальными, а все заказы в тенге должны иметь курс. Затем
исключаются отрицательная выручка, неположительное число билетов и выручка
выше P99. Нулевая выручка сохраняется. После удаления строк интервалы
между оставшимися заказами рассчитываются заново.

Профиль содержит первый и последний заказы, первое устройство, регион
и тип события, число заказов, среднюю выручку и число билетов, средний
интервал между покупками. У разовых покупателей средний интервал остается
пропуском. Основная выборка ограничена P99 числа заказов на пользователя.
Отдельно сохраняются профили и сегментные оценки до этого ограничения.

Под возвратом здесь понимается доля пользователей с двумя и более заказами
в доступном периоде. Это не классический когортный Retention. Дополнительно
рассчитывается возврат за 30 календарных дней, включая день первого заказа
и день 30, только для пользователей с полным окном наблюдения.

Продуктовые гипотезы проверяются описательным сравнением долей и размеров
сегментов. Для долей рассчитаны 95% интервалы Уилсона. Статистические тесты
не применяются. PhiK рассчитывается для числового количества заказов,
групп `1`, `2`, `3-4`, `5+` и отдельно для повторных покупателей. Идентификаторы
и метка повторной покупки не включаются в корреляционную матрицу.

## Итоги анализа

| Показатель | Результат |
| --- | --- |
| Период наблюдения | 01.06.2024-31.10.2024 |
| Исходная SQL-выгрузка | 290 611 заказов, 21 933 пользователя |
| Неявные дубликаты | 42 строки, 31 пользователь |
| Порог выручки P99 | 2 628,42 руб. |
| После очистки | 287 363 заказа, 21 838 пользователей |
| Потери заказов при очистке | 1,12% |
| Порог числа заказов P99 | 152 |
| Основная выборка | 21 622 пользователя, 140 448 заказов |
| Доля повторных покупателей | 61,32% |
| Доля до ограничения активности | 61,70% |
| Повторная покупка за 30 дней | 48,96% среди 17 442 пользователей |

Исключены 216 наиболее активных профилей. На них приходится 51,13%
очищенных заказов, поэтому результаты основной выборки характеризуют
пользователей с обычной активностью. Очистка полностью исключила 95
пользователей, изменила первый сохраненный заказ у 138 и признак повторной
покупки у 60. Только удаление неявных дубликатов не изменило этот признак.

Крупнейшая точка входа по типу события: концерты. Среди типов с не менее
чем 100 пользователями максимальная доля возврата у выставок: 64,16%.
После первого заказа с desktop возвращаются 63,83%, с mobile: 60,80%.

Гипотеза о более высоком возврате после спорта не подтверждается
описательным сравнением: 55,79% против 61,82% у концертов. Среди 29 регионов
с не менее чем 100 пользователями доля возврата составляет 53,67%-67,33%.
Последовательного роста этой доли с размером региона на диаграмме не видно.
Максимальная доля у Шанырского региона.

Медиана средней выручки с заказа у разовых покупателей: 378,9 руб.,
у повторных: 496,5 руб. Центральные 50% значений лежат соответственно
в диапазонах 133,1-831,0 и 271,7-745,6 руб. Доли возврата по дню недели
первой покупки находятся в пределах 59,45%-62,99%.

Наибольшая связь с группой числа заказов по PhiK наблюдается у длительности
наблюдения (0,424), среднего числа билетов (0,335) и средней выручки с заказа
(0,280). PhiK не показывает направление связи и не доказывает причинность.

## Рекомендации

- Тестировать подборки близких мероприятий и напоминания после первого
  заказа в крупных сегментах концертов и mobile. Измерять повторную покупку
  за 30 дней и выручку на пользователя.
- Проверить выставки и Шанырский регион отдельными экспериментами.
  До увеличения бюджета сопоставить состав когорт, интервалы долей,
  стоимость привлечения и маржинальность.
- Для сегментов с низким возвратом изучить ассортимент, доступность
  мероприятий и путь повторной покупки. Спортивную аудиторию не выбирать
  приоритетной только на основании исходной гипотезы.
- Изучить ультраактивные аккаунты отдельно: это могут быть посредники
  или корпоративные клиенты. Большое число покупок не доказывает аномалию.
- Для прогноза использовать одинаковые окна и признаки, известные
  на дату прогноза. Агрегаты всей истории нельзя использовать для прогноза
  возврата сразу после первой покупки без временного разделения.

## Ограничения

Покупки до июня и после октября не наблюдаются. Первый сохраненный заказ
не обязательно является первым за всю жизнь клиента. Названия регионов
и событий анонимизированы. Очистка и ограничение активности меняют выборку;
P99 не доказывает ошибочность исключенных значений. Различия сегментов
могут отражать ассортимент, состав аудитории и календарные когорты.
Проверка за 30 дней уменьшает различие доступного времени наблюдения,
но не устраняет все смешивающие факторы. Выводы применимы к выбранному
периоду, устройствам и типам мероприятий.

## Проверки

```bash
python -m unittest discover -s tests -v
python -m pip check
```

Девять тестов проверяют неявные дубликаты, пересчет интервалов после
очистки, конвертацию с учетом номинала, сохранение нулевой выручки,
профили разовых покупателей, границы 30-дневного окна, сравнение спорта
и концертов, отсутствие курса и параметры загрузки.
